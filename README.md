# maibot-expenses-summary-plus - 麦麦财务总结优化

> ⚠️ **与原版互斥**：本插件是 [davidblackcn/maibot-expenses-summary-plugin](https://github.com/DavidBlackCN/maibot-expenses-summary-plugin)（麦麦财务总结插件）的优化分支，两者共用相同的统计能力、指令与数据目录（`data/ledger.json`），**请勿同时安装**，否则会发生指令冲突与账本数据互相覆盖。安装前请先卸载原版。

一个 MaiBot 1.0.9+ / sdk2.6.0+ 插件，统计当天模型调用次数、回复量和回复成本，并生成财报文本与图片。在保留原版全部功能的基础上，新增**官方牌价引擎**（自定义计价）、订阅制/混合计费口径，以及账本人工修正量。

## 功能

- 统计今日模型请求、回复和成本
- 支持 `/expenses` 和 `/今日财报` 指令立即生成财报
- 支持作为 Tool 被麦麦主动调用
- 支持“默认”和“麦晨风”两种财报模式
- 支持管理员命令在线切换财报模式
- 支持合并转发消息或普通消息发送
- 使用 HTML 渲染图片展示累计请求次数、回复成本和各模型回复成本
- 卡片高度按内容自适应，内容少不留白、内容多不截字
- 财报末尾附带可用指令清单，新人上手与自查都方便（可关）
- **官方牌价引擎**：定时抓取供应商官网价格页，自行按真实单价计价
- 支持**峰谷/时段价**、**缓存命中/未命中/输出三分单价**、**按输入长度分档**、USD/CNY 双币种
- 价格表渲染为图片卡片，支持巨变闸门与管理员确认
- 支持三种计费口径：纯按量、固定月费订阅、订阅+按量混合（`[billing]` 配置）
- 支持账本人工修正量（`/消耗修正`、`/捐赠修正`）
- 可选定时发送

## 财报模式

### 默认模式

默认模式文案偏正常，适合日常查看成本。默认情况下：

1. 第一条消息：今日财报开头语
2. 第二条消息：图片，包含累计请求、回复消息、回复成本、各模型成本

默认模式第一条文本可通过 `report.default_opening` 修改，支持 `{date}` 占位符。

### 麦晨风模式

让你的麦麦化身“户晨风本风”，每天用咬牙切齿的语气公开处刑自己（并顺带感谢股东）：

1. 第一条消息：麦晨风风格开头语
2. 第二条消息：图片，包含累计请求、回复消息、回复成本、各模型成本
3. 第三条消息：感谢文案

## 官方牌价引擎（Pricing）

### 为什么需要它

麦麦自带的 `statistics` 能力只开放 `request` / `cost` / `latency` / `total_tokens` 四种口径，
**拿不到「缓存命中 / 缓存未命中」的拆分**。而 DeepSeek 系模型的缓存命中价往往只有未命中价的几十分之一，
拿不到这个拆分就算不出真实成本。

因此 v2.0 起改为**直接只读麦麦的账单表**（`llm_usage`），逐条按官方牌价计价。
实测定量：某模型在硅基渠道的累计用量，麦麦原生口径记 ¥1.97，按官方牌价实为 ¥6.58（相差 3.3 倍）。

### 工作方式

1. **抓取**：每天在 `refresh_time` 抓取各供应商官网价格页（确定性代码）
2. **解析**：把页面文本交给 LLM，产出结构化价带（语义解析，页面改版不会静默失效）
3. **校验**：字段校验 + 合理性边界，非法价带直接丢弃，不允许降级成全时段兜底价
4. **闸门**：与现役价目表比对，单价变化超过阈值或出现新增/消失的价带时挂起，等管理员确认
5. **计价**：按「小时桶 × 模型 × 供应商 × 输入档位」聚合账单，逐桶套价带

### 价带结构

每个模型由若干「价带」组成，能同时表达四种情况：全时段统一价、峰谷分时、凌晨优惠时段、按输入长度分档。
每个价带记录：适用时段（时区 + 小时段 + 星期）、输入档位、以及缓存命中 / 未命中 / 输出三个单价 + 币种。

### 兑底策略

- 价格文件损坏 → 用上一版
- 某模型没有牌价 → 用麦麦原生 `cost` 并在财报里标注
- 抓取失败 → 当天不更新，日志留痕，绝不静默改数

### 指令

```text
/价格              # 查看现役价目表（渲染为图片卡片）
/价格刷新          # 立即抓取一次，不等定时
/价格确认          # 应用被挂起的变更
/价格否决          # 丢弃被挂起的变更
```

均为管理员可用。

### 账本重算

`pricing.rebuild_ledger = true` 时，牌价首次生效会用真实牌价重算账本里的历史开销（只改 `cost`，不动投喂记录）。
重算范围从 `pricing.rebuild_from` 指定，留空取账本最早一天。

> 注意：重算用的是「当前牌价」而非「当时牌价」，历史时段判定是准的（按真实时间戳），但无法复原已调价的部分。

## 计费模式（Billing）

财报成本默认来自 MaiBot 统计接口的按量估算口径（token 用量 × 单价）。当模型通过固定月费订阅渠道（如 OpenCode Go 等按计划订阅的模型）使用时，按量估算会失真。`[billing]` 配置节提供三种计费口径：

| 模式 | 说明 |
|------|------|
| `usage` | 纯按量（默认，原口径）：成本直接取统计接口的按量估算值 |
| `subscription` | 纯订阅：所有模型成本按固定月费折算，不使用按量估算 |
| `hybrid` | 混合（推荐）：订阅模型走月费折算，其余模型按量照算 |

配置示例：

```toml
[billing]
mode = "hybrid"                # usage | subscription | hybrid
currency = "usd"               # 订阅支付币种：usd=美元计费 | cny=人民币计费（不换算汇率）
renew_day = 14                 # 每月续费日（扣款日，1-31；大于当月天数时取月末）
renew_amount = 10.0            # 每期续费金额（续费日到下个续费日扣款额）
share_daily = true             # true=按本期天数均摊为日均成本；false=整期费用一次展示
subscription_models = ["-go"]  # hybrid 模式：模型名包含任一关键词即视为订阅（子串匹配）
exchange_rate = 7.2            # 兜底汇率：usd 计费且自动获取汇率失败时使用
```

### 订阅周期

每期从续费日（`renew_day`）到下个续费日。今日订阅成本 = 每期续费金额折算人民币 ÷ 本期天数。续费日为 31 号时，无 31 号的月份自动取月末（如 2 月取 2/28），下一期从下月实际续费日接续。

### 汇率获取

USD 计费时，汇率优先取**续费当天的历史牌价**（frankfurter 公开接口），同一订阅周期内缓存快照、不重复请求；历史接口不可用时回退实时接口，再失败用 `exchange_rate` 兜底。CNY 计费完全不参与汇率换算。

### 财报展示

- 订阅模型在图片中显示橙色「订阅包」标签，横条为橙色，按量成本置零
- 按量模型照常显示金额（深青色横条）
- 「回复成本」卡片下方显示口径说明小字（币种、汇率、周期、均摊方式）
- 净收入、账本累计开销均按新口径记账

### 账本人工修正量

财报里的成本是按官网清单价**估算**的消耗价值，不等于你实际掏的钱。
为此账本支持人工修正量，用来补差价（例如没走记账的充值、赠送额度、订阅支出）：

```text
实际总消耗 = 账本估算消耗 + 消耗修正量
实际总捐赠 = 账本记录捐赠 + 捐赠修正量
```

```text
/消耗修正 120.5      # 设定消耗修正量
/消耗修正 +50        # 在现有修正量上累加（带符号即累加）
/消耗修正 清空       # 清零，回到估算口径
/消耗修正            # 只查看当前口径
/捐赠修正            # 同上，作用于投喂侧
```

修正量存在 `ledger.json` 的 `manual` 字段。财报卡片、转发文案和 `/账本` 三处都会展示
「估算 + 修正 = 实际」的拆解。

管理员可切换模式：

```text
/财报模式 默认
/财报模式 麦晨风
/expensesmode default
/expensesmode maichenfeng
```

`/财报模式` 和 `/expensesmode` 始终仅管理员可用。管理员通过 `permission.admins` 配置 QQ 号。

### 记账（账本）

记录群友投喂 / 开销，数据存 JSON 账本（`data/ledger.json`）：

```text
/记账 <金额> [备注]      # 例：/记账 71 抹茶味兽兽
/投喂 <金额> [备注]      # 记账的别名
/账本                   # 查看累计账本
/查账                   # 查看累计账本（别名）
/投喂史                 # 查看历史全部投喂记录（按日期时间列出每笔明细与合计）
/历史投喂               # 投喂史的别名
/投喂记录               # 投喂史的别名
/donations              # 投喂史的别名
```

- 成功回复格式：`已记账：71.00 元（抹茶味兽兽）。累计投喂 X 元，累计开销 X 元，净收入 X 元。`
- 默认**仅管理员可用**（`ledger.admin_only` 可配，`permission.admins` 指定管理员 QQ）
- 账本功能总开关：`ledger.enabled`（默认开）

## 配置

仓库提供 `config.example.toml`，可作为默认配置参考。主要配置如下：

```toml
[plugin]
config_version = "2.0.0"

[report]
mode = "default"
title = "今日模型调用财报"
llm_task = "utils"
use_forward_message = true
nickname = "麦麦"       # 转发消息内的昵称；留空自动取机器人昵称
default_opening = "{date}模型调用财报已生成，以下是今日请求次数、回复量与模型成本汇总。"
show_commands = true    # 财报末尾附带可用指令清单
commands_hint = ""      # 自定义指令清单文本；留空用内置默认

[permission]
query_admin_only = false
admins = []

[scheduler]
enabled = false
time = "23:30"
group_ids = []
private_ids = []

[fallback]
xiao_names = ["孙笑川"]
locations = ["家里", "直播间", "工作室", "走廊"]
poems = [
  "今天也是嘴硬的一天。",
  "气冷抖，孙狗什么时候才能站起来？",
  "我永远喜欢孙笑川！",
  "大家都很聪明，就是有点笨。"
]
thanks_list = ["孙笑川：114514", "抽象带篮：1919810", "吃花椒的喵酱：810"]

[billing]
# 计费模式：usage=纯按量(原口径) | subscription=固定月费 | hybrid=订阅模型+其余按量混合
mode = "usage"
# 订阅支付币种：usd=美元计费（按续费日汇率折人民币）| cny=人民币计费（不换算汇率）
currency = "usd"
# 每月续费日（扣款日，1-31；大于当月天数时取月末）
renew_day = 14
# 每期续费金额（续费日到下个续费日扣款额，配合 currency 使用）
renew_amount = 10.0
# true=把本期订阅费按周期天数均摊为日均成本；false=整期费用一次展示
share_daily = true
# hybrid 模式生效：模型名包含任一关键词即视为订阅（子串匹配）
subscription_models = ["-go"]
# usd 计费且自动获取汇率失败时使用的兜底 USD→CNY 汇率
exchange_rate = 7.2

[pricing]
# 官方牌价引擎：定时抓取供应商价格页，按真实单价自行计价。
# 关闭后成本退回麦麦原生口径，但不再依赖「缓存命中/未命中」拆分。
enabled = true
# 是否每天自动抓取
auto_refresh = true
# 每天抓取时刻（HH:MM）
refresh_time = "04:10"
# 解析价格页用的模型任务名；留空用 report.llm_task
llm_task = "utils"
# 「巨变」阈值：任一单价相对现役值的涨跌幅超过该百分比，
# 或出现新增/消失的价带，就挂起等待管理员确认
change_threshold_percent = 20.0
# 关闭后即使超过阈值也直接自动应用
require_admin_confirm = true
# 某模型没有牌价或取数失败时，退回该模型在麦麦里的原生 cost
fallback_to_native_cost = true
# 首次生效价格时，用官方牌价重算账本里的历史开销（只改 cost，不动投喂记录）
rebuild_ledger = true
# 账本重建起始日（YYYY-MM-DD）；留空自动取账本最早一天
rebuild_from = ""
# 覆盖内置价格源，格式：供应商=页面地址
sources = []

# BGM 音频功能自 1.0.1 起暂停启用：当前 sdk2.x 暂未提供 send.audio 能力。
```

`report.use_forward_message = true` 时使用合并转发消息发送；设为 `false` 时会按普通消息逐条发送文本和图片。

`report.nickname` 用于指定合并转发消息内各节点的昵称，留空时自动解析机器人昵称（多源回退），取不到则用默认名。设为与 QQ 端账号显示名一致即可保证转发内外观感统一。

`report.llm_task` 用于配置麦晨风模式生成地点、“我去了……”和诗句时使用的任务名，插件会通过 SDK 公共接口 `ctx.llm.generate(..., model=report.llm_task)` 调用，默认使用 `utils`。小名不会交给 LLM 生成，只会从 `fallback.xiao_names` 中选择。

`permission.query_admin_only = true` 时，`/expenses` 和 `/今日财报` 仅管理员可用；模式切换命令始终仅管理员可用。

`scheduler.enabled = true` 时会按 `scheduler.time` 每天定时发送。`scheduler.group_ids` 填 QQ 群号，`scheduler.private_ids` 填私聊 QQ 号，插件会通过 `ctx.chat.get_stream_by_group_id()` / `ctx.chat.get_stream_by_user_id()` 解析目标会话后发送。

麦麦在需要“生成今日财报”“公开模型调用成本”“麦晨风式收入汇报”等场景下可以调用 `expenses_summary`。

## 安装

将插件目录放入 MaiBot 的插件目录，确认 `_manifest.json` 与 `plugin.py` 位于同一目录后重启 MaiBot。

## 兼容性

- MaiBot 最低版本：`1.0.9`
- SDK 版本：`2.6`

插件使用 `ctx.statistics.local.*` 获取统计数据，使用 `ctx.render.html2png()` 生成图片。合并转发模式使用 `ctx.send.forward()`，普通消息模式使用 `ctx.send.text()` 和 `ctx.send.image()`。

统计口径：MaiBot 统计 API 的 `days` 参数表示最近 N 天数据；插件会使用小时粒度趋势数据，并按本地日期过滤为当天 0 点至当前时间，避免新的一天继续计入前一日的 24H 数据。

成本口径（v2.0 起）：`ctx.statistics.local.*` 只用于请求数与回复量；**成本改由插件直接只读账单表 `llm_usage` 计算**。
数据库路径由插件数据目录向上推算（`<MaiBot>/data/MaiBot.db`），只读打开（`mode=ro` + `PRAGMA query_only`），不写入。
`statistics_model_hourly` 表缺备份字段，无法用于缓存分化计价，故不走它。

## 更新日志

### 2.0.4

- 价带结构签名改为**时区归一化**：先把 `tz + hours` 换算到 Asia/Shanghai 再生成签名，
  避免 `UTC 01:00-04:00` 与 `Asia/Shanghai 09:00-12:00` 这类等价时段被当成「消失 + 新增」的假结构变化。
- 没有 tzdata 的环境下对 UTC 做 +8 兜底。

### 2.0.3

- DeepSeek 默认抓取源改为**中文价目页**（`zh-cn/quick_start/pricing`），抓回来直接是人民币价，
  不再需要手动把 `prices.json` 改成 CNY，也不会再出现 USD 与 CNY 混比。
- 若你的部署环境需要英文页或其它镜像，可在 `[pricing].sources` 里用 `供应商=地址` 覆盖。

### 2.0.2

- 修复牌价比对闸门的**币种混比**：`_flatten_price_points` 现在会先把 USD 条目按当前汇率折算为人民币，
  再与 CNY 条目逐项比较。此前人民币价与美元价被直接相减，会出现「2 → 0.3，降幅 85%」这类假警报。
- 汇率优先取 `billing.exchange_rate` 或当日缓存，缺省 7.2。

### 2.0.1

- 卡片高度改为**按内容自适应**：报告卡片原先带 `min-height: 1200px`，内容少时会留一大片空白；
  同时把渲染调用改为 `selector=body` + `full_page=True`（宿主的 `full_page` 仅在 `selector==body` 时生效）。
- 财报末尾附带**可用指令清单**（`report.show_commands` 开关、`report.commands_hint` 自定义文本），
  解决新人和自己都记不住指令的问题。

### 2.0.0

**成本改为按官方牌价自行计算，不再依赖麦麦内置价格表。**

起因：`statistics` 能力只开放 `request` / `cost` / `latency` / `total_tokens` 四种口径，
拿不到「缓存命中 / 未命中」拆分，而命中价往往只有未命中价的几十分之一，
直接用会导致成本被系统性低估（实测某模型累计用量：原生口径 ¥1.97，官方牌价 ¥6.58）。

- 新增**官方牌价引擎**：定时抓取供应商价格页 → LLM 解析为结构化价带 → 字段校验 → 比对闸门 → 逐桶计价。
- 新增 `[pricing]` 配置节（抓取开关与时刻、解析模型、巨变阈值、兑底、账本重算、价格源覆盖）。
- 新增巨变闸门：单价变化超过 `change_threshold_percent`（默认 20%）或出现新增/消失的价带时挂起；
  **首次建表同样挂起**，避免错价静默生效。
- 新增 `/价格`（价目表渲染为图片卡片）、`/价格刷新`、`/价格确认`、`/价格否决` 四个管理员命令。
- 新增账本人工修正量：`/消耗修正`、`/捐赠修正`，实际总额 = 账本值 + 修正量（带符号累加、支持清零）。
- 新增 `pricing.rebuild_ledger`：首次生效牌价时按真实价重算账本历史开销（只改 `cost`，不动投喂记录）。
- 修复 hybrid 口径下订阅模型被重复计费：订阅关键词（如 `-go`）只出现在模型**别名**里，
  而账单表存的是**真实模型名**，原先的子串匹配从未生效。现在按供应商 / 真实模型名 / 别名三者联合匹配。
- 重算逻辑加版本号，口径修正后会在下次插件加载时自动重算一次。
